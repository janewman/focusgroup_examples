Question being explored

Should nested-control behavior be independently configurable?

This page treats itemcontrols as a separate hypothetical attribute. The names mirror the modes discussed in issue #1500, but the keyboard details here are only one possible interpretation.

01 · Independent configuration

itemcontrols attribute

This sketch makes nested-control behavior independent from focusgroup. Arrow through the values to update every example on this page, then Tab into the examples. The attribute only manages nested controls; it never changes a container’s authored focusability.

02 · Working interpretation

What each token means here

These definitions are intentionally concrete enough to test, not normative.

absentNative sequence

Without the attribute, the authored container and controls retain their ordinary focusability.

no-tabExplicit entry, looped

Enter opens the controls, Tab loops within them, and Escape returns to the card.

tab-exitExplicit entry, escapable

Enter opens the controls. Tab from the final control leaves the card.

tab-onlySequential entry and exit

The boundary and nested controls appear naturally in the Tab sequence.

inlinedirectionInline-axis entry

Inline-end enters nested controls; inline-start returns to the item boundary.

blockdirectionBlock-axis entry

Block-end enters nested controls; block-start returns to the item boundary.

03 · Directional entry

Cross-axis submenu

Up and Down choose a menu item. With inlinedirection, Right Arrow enters its submenu and Left Arrow returns. Each parent owns a nested block-axis focusgroup; the shared control above can try every value.

04 · Composing behaviors

Standalone itemcontrols inside focusgroups

The current explainer puts the itemcontrols modifier on the focusgroup owner. These examples instead put the standalone attribute on each item that owns nested controls. The outer attribute describes only spatial navigation.

Action list owner: focusgroup="toolbar block" items: itemcontrols="inlinedirection"

Up and Down change the active layer; Tab enters only that layer’s actions.
