Question being explored

One attribute, standalone or composed with focusgroups?

This page treats itemcontrols as a separate hypothetical attribute. The names mirror the modes discussed in issue #1500, but the keyboard details here are only one possible interpretation.

01 · Standalone

Standalone itemcontrols

This sketch makes nested-control behavior independent from focusgroup. Arrow through the values to update this standalone example, then Tab into it. The attribute only manages nested controls; it never changes a container’s authored focusability.

02 · Shared vocabulary

Values in either context

These definitions are intentionally concrete enough to test, not normative.

absentNative sequence

Without the attribute, the authored container and controls retain their ordinary focusability.

no-tabExplicit entry, looped

Enter opens the controls, Tab loops within them, and Escape returns to the card.

tab-exitExplicit entry, escapable

Enter opens the controls. Tab from the final control leaves the card.

tab-onlySequential entry and exit

The boundary and nested controls appear naturally in the Tab sequence.

inlineentryInline-axis boundary

Inline-end enters nested content; inline-start returns. It does not navigate within.

blockentryBlock-axis boundary

Block-end enters nested content; block-start returns. It does not navigate within.

04 · Per-item specialization

A workspace with mixed interaction contracts

This is the capability an owner-level value cannot express: each item chooses an entry contract that matches its nested widget. Up and Down move between item boundaries; the visible keyboard hint explains how to enter each item.
